# Деплой: результаты уроков

2 октября 2026

Django-приложение: ученики сдают скриншоты урока, родители смотрят их по личной ссылке. Это два контейнера (app + nginx) в docker compose, база SQLite и файлы на томах. HTTPS не входит в compose и нужен снаружи. Образ ещё ни разу не собирался.

## Как устроено

```
                                         ┌─ docker compose ───────────────────────────┐
┌────────────┐    ┌──────────────────┐   │  ┌───────────────┐      ┌───────────────┐  │
│  Браузер   │───▶│  Внешний прокси  │───┼─▶│   nginx :80   │─────▶│   app :8000   │  │
│  ученики,  │    │ TLS, 500 МБ,120 с│   │  │ /media/ с     │      │ Django +      │  │
│  родители  │    │     (на вас)     │   │  │ диска, прочее │      │ gunicorn,     │  │
└────────────┘    └──────────────────┘   │  │ в app         │      │ 3 воркера     │  │
                                         │  └───────┬───────┘      └──┬─────────┬──┘  │
                                         │    чтение│         запись  │         │     │
                                         │          ▼                 │         ▼     │
                                         │  ┌───────────────┐◀────────┘ ┌──────────┐  │
                                         │  │   том media   │           │ том db · │  │
```

Стек: Python 3.12, Django 5.2, gunicorn, whitenoise (статика), nginx 1.27 (скриншоты), SQLite. Кроме томов, в `app` read-only смонтирована папка `./students` с CSV. Все файлы деплоя: `Dockerfile`, `docker-compose.yml`, `deploy/nginx.conf`, `deploy/entrypoint.sh`, `.env.example`.

## Запуск

Нужны Docker и compose v2. Git-репозитория у проекта пока нет, код передаётся папкой.

1. Скопировать `.env.example` в `.env` и заполнить (таблица ниже). Ключ: `python3 -c "import secrets; print(secrets.token_urlsafe(50))"`.
2. Положить актуальные CSV учеников в `./students/` (`students_<филиал>.csv`, колонки `ID`, `ФИО`, UTF-8).
3. `docker compose up -d --build` — миграции применяются сами при старте `app`.
4. `docker compose exec app python manage.py import_students` — загрузить учеников. Повторный запуск безопасен: обновляет ФИО по `ID`, токены ссылок не меняются.
5. `docker compose exec app python manage.py createsuperuser` — вход в `/admin/`.
6. Проверить: `/` открывает список учеников, `/admin/` — админку со стилями.

Когда пришлют новые CSV: заменить файлы в `./students/` (папка смонтирована read-only) и повторить шаг 4. Пересборка не нужна.

## Переменные окружения (`.env`)

| Переменная | Обязательна | Значение |
| --- | --- | --- |
| `DJANGO_SECRET_KEY` | да | Без неё при `DEBUG=0` контейнер падает на старте — это намеренно |
| `DJANGO_ALLOWED_HOSTS` | да | Домен(ы) через запятую, без схемы |
| `DJANGO_CSRF_TRUSTED_ORIGINS` | да за HTTPS | `https://<домен>`; без неё отправка скриншотов и вход в админку дают 403 |
| `PUBLIC_BASE_URL` | желательно | `https://<домен>` — из него строятся ссылки для родителей в админке и CSV-выгрузке |
| `DJANGO_SECURE_COOKIES` | `1` за HTTPS | Secure-куки и доверие заголовку `X-Forwarded-Proto` |
| `HTTP_PORT` | нет | Порт nginx на хосте, по умолчанию 80 |
| `DJANGO_DEBUG` | нет | В образе уже `0` |

`DJANGO_DB_PATH` и `DJANGO_MEDIA_ROOT` заданы в Dockerfile (`/data/db/db.sqlite3`, `/data/media`), трогать не нужно. Часовой пояс приложения — `Asia/Almaty`: дата урока берётся по нему.

## Требования к внешнему прокси

nginx в compose слушает только HTTP. TLS должен делать прокси перед ним (Caddy, Traefik, nginx на хосте + certbot, балансировщик хостинга).

- **HTTPS обязателен.** По ссылкам ходят родители, а кнопка «Вставить из буфера» в браузере работает только на HTTPS.
- **Размер запроса — до 500 МБ.** Ученик отправляет до 30 скриншотов по до 15 МБ одним POST на `/upload/`. Реально это чаще 5–20 МБ, но лимит прокси должен быть не меньше, чем у нашего nginx (`client_max_body_size 500m`). Если стоит Cloudflare на бесплатном тарифе, у него потолок 100 МБ — лучше сказать, снизим лимит в коде.
- **Таймауты — не меньше 120 с** на чтение тела и ответ: в классе медленный Wi-Fi. Столько же стоит у нашего nginx и gunicorn.
- **Передавать `X-Forwarded-Proto: https` и `Host`.** И выставить `DJANGO_SECURE_COOKIES=1`.
- **Не светить порт compose-nginx наружу.** Он прокидывает `X-Forwarded-Proto` от клиента как есть, так что прямой доступ позволяет его подделать. Привязать к localhost: `HTTP_PORT=127.0.0.1:8080` (и прокси на `127.0.0.1:8080`) или закрыть файрволом.

Если проще, можно добавить в compose Caddy с автоматическими сертификатами — нужен только домен с A-записью на сервер.

## Данные и бэкапы

Всё состояние — в двух именованных томах, контейнеры можно пересоздавать свободно. Не делать `docker compose down -v`.

| Том | Путь в контейнере | Что в нём |
| --- | --- | --- |
| `db` | `/data/db` | SQLite (WAL), ученики, токены ссылок, админы |
| `media` | `/data/media` | Скриншоты; nginx монтирует его read-only |

- **Только одна реплика `app` на одном хосте** — из-за SQLite и локальных файлов. Внутри 3 воркера gunicorn, для четырёх филиалов (~125 учеников) этого хватает. Для нескольких реплик нужны Postgres и S3 — это доработка.
- **Рост диска:** скриншоты не сжимаются. Грубая оценка: 125 учеников × 3 скриншота × ~1 МБ ≈ 0,4 ГБ в неделю при одном уроке. Поставить алерт на место.
- **Переезд на S3 запланирован:** django-storages + замена `STORAGES['default']`. После него том `media` и `location /media/` в nginx не нужны, а старые файлы копируются в бакет с теми же путями.

Бэкап (SQLite копируем через backup API, а не `cp`, чтобы не поймать битый файл при WAL):

```bash
docker compose exec app python -c "import sqlite3; sqlite3.connect('/data/db/db.sqlite3').backup(sqlite3.connect('/data/db/backup.sqlite3'))"
docker run --rm -v <проект>_db:/db -v <проект>_media:/media -v "$PWD":/out alpine \
  tar czf /out/backup-$(date +%F).tar.gz /db/backup.sqlite3 /media
```

Имена томов покажет `docker volume ls`. Потеря базы = потеря токенов: ссылки, уже разосланные родителям, перестанут работать. Нужен ежедневный бэкап вне сервера.

## Безопасность

В системе ФИО детей и их работы, доступ к галерее — только по секретной ссылке, без логина.

- **Ссылки `/s/<токен>/` — bearer-секреты** (16 символов urlsafe). Не писать их в публичные логи и аналитику; аксесс-логи на сервере их содержат — это нормально.
- **`/media/` отдаётся nginx без проверки доступа.** Защита — неугадываемые пути (`screenshots/<токен>/<дата>/<uuid>.png`). Не включать `autoindex`. Стоит `X-Robots-Tag: noindex`.
- **Админка `/admin/` открыта в интернет.** Защиты от перебора паролей нет. Хорошо бы ограничить на прокси (IP офиса/VPN или basic auth) или хотя бы rate limit.
- **Страница сдачи `/` и `/upload/` публичные по задумке:** ученик просто выбирает себя из списка. Значит, список ФИО виден любому, и любой может залить картинки. Если у филиалов статические IP, лучше открыть `/` и `/upload/` только для них, а `/s/` и `/media/` оставить всем.
- **CSV с ФИО вшиты в образ** (`COPY . .`). Не пушить образ в публичный registry; либо добавить `students/` в `.dockerignore` — в рантайме папка всё равно монтируется из compose.
- Контейнер `app` работает от пользователя `app` (uid 1000), не root.

## Обновление, логи, проверка

- **Обновление кода:** заменить файлы → `docker compose up -d --build`. Миграции прогоняются на старте в `deploy/entrypoint.sh`, статика собирается при сборке и отдаётся whitenoise. Простой на время перезапуска — несколько секунд; не делать в конце урока.
- **Логи:** `docker compose logs -f app nginx`. Django и gunicorn (включая access log) пишут в stdout.
- **Хелсчека нет.** Для мониторинга подойдёт `GET /` → 200. При желании добавлю `/healthz` и `healthcheck` в compose.
- **Смоук-тест после деплоя:** на `/` выбрать любого ученика, вставить скриншот Ctrl+V и отправить; в `/admin/` открыть этого ученика, перейти по ссылке для родителей и увидеть картинку; удалить её в админке.

- [ ] Первая сборка `docker compose up --build` с просмотром логов; особенно права на запись в тома от uid 1000
